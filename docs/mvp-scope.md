# MVP 范围与技术边界

## 要解决的问题

用户上传一份合同或招标文件后，系统回答条款问题，并为每条结论提供可核对的条款号与原文引用。引用无法通过校验时，系统有限重检索；仍无依据则明确拒答。

## 必做范围

| 模块 | 验收结果 |
| --- | --- |
| 文档入库 | 至少 10 份脱敏文档可解析，失败文件有原因记录 |
| 条款切分 | 条款编号与原文一致，保留章节路径和页码 |
| 检索问答 | CLI 可完成单文档问答，返回结构化答案与引用 |
| 混合检索 | BM25 + 向量召回，RRF 融合，重排保留 top-5 |
| 引用校验 | 原文子串核对 + 语义支撑判断，生成校验报告 |
| 回退拒答 | 最多重检索 2 轮，不可答题最终明确拒答 |
| 离线评测 | 60 条四类评测，一键输出 JSON 与 Markdown 报告 |
| Web 演示 | 上传、问答、引用跳转与原文高亮可用 |

## 二期候选

多文档对比、条款冲突检测、风险等级标注、对话记忆与追问、导出审查意见。只有 MVP 验收通过后才考虑。

## 明确不做

- **扫描件 OCR 全流程**：本期先验证文本型 PDF，避免解析工程吞掉核心开发时间。
- **法律意见生成**：系统提供原文定位，不替代专业法律判断。
- **多人权限体系**：单用户演示即可验证核心检索与校验能力。
- **移动端**：桌面 Web 已足够展示溯源交互。
- **向量数据库集群**：本地 Chroma 足以验证检索质量，不引入运维复杂度。

## 技术选型

Python 3.11+、LangGraph、PyMuPDF、Chroma、rank_bm25、云端嵌入/生成 API、bge-reranker 或 API 重排、Streamlit、uv、ruff、pytest、structlog。

每次替换选型必须记录：解决的问题、备选方案、指标变化与新增成本。
